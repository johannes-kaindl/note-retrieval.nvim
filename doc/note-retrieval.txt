*note-retrieval.txt*  Related notes and semantic search over a Markdown vault

Related notes and semantic search over a folder of Markdown notes. The plugin reads one index of the vault and writes only its own: the index of the Obsidian plugin Vault Retrieval is only read (mode `obsidian`), otherwise the plugin keeps its own index (shown as `eigen` by `:NoteRetrieval status`). Pages outside Neovim: docs/README.md in the plugin's repository.

==============================================================================
COMMANDS                                                *:NoteRetrieval*

:NoteRetrieval related
	Open or close the panel on the right with the notes related to the note you are in. It follows you from note to note and needs no server: the notes are read from the index. Keys in the panel: <CR> opens a note, `l` writes a link to it (see |note-retrieval-option-link_format|), `q` closes.

:NoteRetrieval search [query]
	Search the notes by meaning: the query is embedded once, the closest notes are listed, the one you pick opens. Without a query it asks for one.

:NoteRetrieval status
	Show the notes folder, the mode, the index, the number of notes, the model, the age of the index and the servers. The index and the settings of the vault are read once per session.

:NoteRetrieval model
	Choose the embedding model of a server; with several servers that list models, the server is asked first, then its model. The choice is remembered per server. An index of the Obsidian plugin decides the model of a search by itself.

:NoteRetrieval probe [n] [--json]
	Check that the index finds what it holds: up to `n` notes (default 40) whose text, without front matter and trimmed, is 201 to 800 UTF-16 code units long are searched with the first 300 units of their own text, one query after another, and each should come back first. Shows `x/n on rank 0` and every other note with its rank. A note that stands behind a hit with exactly its own score (notes with the same vector; the order between them is arbitrary) is a tie, not a miss: the line says `tie`, the header counts ties and real misses apart (`7/8 on rank 0 (1 tie with the best hit, 0 real misses)`), and only real misses make the message a warning. `--json` prints one JSON line (`n`, `hits`, `ties`, `misses`, `rate`, `failures`, `seed`, `model`; each failure has `path`, `rank`, `top`, `score`, `top_score`, `tie`). It only reads, so it works on the index of the Obsidian plugin too.

:NoteRetrieval reindex
	Build the plugin's own index again from all notes, in the background; `:NoteRetrieval status` shows the progress. Only in the own mode: an index of the Obsidian plugin is never written, the command says so. Takes the model from |note-retrieval-option-embedding_model| or the remembered choice. After a full reindex a probe of 8 notes runs (see |note-retrieval-option-probe_auto|). A run in which some notes cannot be embedded writes the others and reports how many are missing; run it again to try them. A write that would leave less than half of the rows of the file is refused.

:NoteRetrieval update
	Bring the own index in line with the notes: embed notes that are new, newer on disk than their row, or whose row holds an all-zero vector, drop the rows of deleted notes, write once; in the background. A batch of saved notes that still waits is written first. Notes in folders that cannot be read keep their rows. The first step (walk of the vault and reload of the index) stalls Neovim for a moment, about 45 to 90 ms on 10000 to 11000 notes, about 150 ms at 20000 when the index is read again. The guard `shrink` refuses an update that would drop more than half of the rows while the files exist (also rows of notes that are empty after the front matter); a vault folder read only in part drops no row; `:NoteRetrieval reindex` is the way out.

:NoteRetrieval stop
	Ask a running reindex to stop after the notes in flight; what it reached is written, the rest of the index is as it was. It does not act on a running update: it then says that the update is running and cannot be stopped, and the update runs on.

:NoteRetrieval reset
	Forget the index, the vault settings, the attach to saves, the waiting batch of saved notes and the one-time hint held in memory; the next command reads them again, for example after editing `data.json` of the Obsidian plugin. A running reindex is left alone and the message says so.

==============================================================================
UPDATE ON SAVE                                           *note-retrieval-on-save*

With |note-retrieval-option-index_on_save| (default true), saving a `*.md` note of a vault with an own index updates the index: after 1000 ms of quiet all notes saved in that window are embedded and written in one batch. Never in the mode `obsidian`. In a session where nothing has started an indexer yet (no update or reindex), a save only prints once per vault `saved notes are not indexed yet in this session; run :NoteRetrieval update once to start`; it never asks for a model. Quitting within a second of a save loses that batch; the next `:NoteRetrieval update` embeds the note.

==============================================================================
LIMITS                                                   *note-retrieval-limits*

- The mark `changed since the index` in the panel is exact only for rows with a real stamp (modification time and size). Rows written by the Obsidian plugin have none; for them the panel says `may be stale, index from <date time>`, a lower bound: the file is newer than the index was built. Nothing re-stamps a row.
- A write is refused, not merged, when another Neovim wrote the file between read and write (`changed`); run the command again.
- The lock is taken per write, not for a whole reindex.
- The picker of `:NoteRetrieval model` waits for all servers.
- A query is embedded with no instruction in front, because the index holds vectors of the raw text of the notes.

==============================================================================
MAPPINGS                                                 *note-retrieval-mappings*

The plugin sets no key of its own; map these (|<Plug>|) to keys you like.

*<Plug>(note-retrieval-related)*
  Normal mode: same as `:NoteRetrieval related`.

*<Plug>(note-retrieval-search)*
  Normal mode: same as `:NoteRetrieval search`. Visual mode: the selected text is the query.

==============================================================================
LUA API                                                  *note-retrieval-api*

`require('note_retrieval').search(query, opts, cb)`
  `cb(results)` or `cb(nil, err)`; results are `{ path, score, title }`, best first. `opts` is `{ k, min_similarity, exclude, root }`.

`require('note_retrieval').related(path, opts)`
  The same list for the note at `path`, read from the index (no server call), or `nil, message`.

`require('note_retrieval').status()`
  A table with `root`, `mode`, `rows`, `model`, `age`, `endpoints`, `warning`, `problem` and `line`, a short text for a status line.

`:checkhealth note_retrieval` checks Neovim, `curl`, the notes folder, the index, the options and the servers, and says what to do about each problem.

==============================================================================
OPTIONS                                                  *note-retrieval-options*

Set them in `vim.g.note_retrieval` or pass them to `require('note_retrieval').setup()`; `setup()` wins field by field. Nothing needs `setup()`. A value that fails its check is reported (`:checkhealth note_retrieval`) and keeps its default.

*note-retrieval-option-embedding_model*
  string, default nil (chosen per server). The model that embeds notes and queries.

*note-retrieval-option-endpoints*
  list of tables, default nil (Ollama, then LM Studio). Embedding servers in priority order; invalid endpoints stop a run.

*note-retrieval-option-hide_linked*
  boolean, default true. Leave out notes the current note already links to.

*note-retrieval-option-exclude*
  list of strings, default nil (none). Path prefixes, relative to the root and case-sensitive, left out of the notes of the plugin's own index, for example `{ 'Templates/' }`; an Obsidian index brings its own list.

*note-retrieval-option-index_dir*
  string, default nil (under `stdpath('data')`). Folder inside the root that holds the plugin's own `index.bin`; an index of the Vault Retrieval plugin found there is only read.

*note-retrieval-option-index_on_save*
  boolean, default true. Update the plugin's own index when a note is saved.

*note-retrieval-option-k*
  integer, default 20. How many related notes to show.

*note-retrieval-option-link_format*
  "wiki" or "markdown", default "wiki". How an inserted link is written.

*note-retrieval-option-min_similarity*
  number from -1 to 1, default 0.3. Cosine similarity below which a note is not related.

*note-retrieval-option-probe_auto*
  boolean, default true. After a full reindex of the plugin's own index, run `:NoteRetrieval probe` on 8 notes and show one line with the result.

*note-retrieval-option-roots*
  list of strings, default nil. Directories holding the notes.

*note-retrieval-option-timeout_ms*
  integer, default 30000. How long one embedding request may take.
